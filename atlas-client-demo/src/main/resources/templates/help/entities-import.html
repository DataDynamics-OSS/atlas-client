무엇을 하나요?

YAML, JSON, CSV로 쓴 엔티티 목록을 읽어 Atlas에 보냅니다. 이미 있는 엔티티는 수정하고 없는 엔티티는 새로 만듭니다 (upsert). 같은 엔티티인지는 타입 + qualifiedName으로 판단하므로, 같은 파일을 여러 번 올려도 중복이 생기지 않습니다.

그래서 모든 엔티티에 qualifiedName이 꼭 있어야 합니다. 없으면 보내기 전에 오류를 표시합니다.

사용 순서

  1. 형식을 고릅니다(yaml, json, csv). 편집기의 문법 강조가 형식에 맞게 바뀝니다.
  2. 편집기에 내용을 쓰거나 붙여 넣습니다. 또는 파일을 고릅니다. 파일을 고르면 편집기 내용 대신 파일을 쓰고, 형식은 파일 확장자(.csv, .json, .yaml)로 정합니다.
  3. 먼저 dry run을 눌러 제대로 읽히는지 확인합니다. Atlas에는 아무것도 보내지 않고, 읽은 결과를 JSON으로 보여줍니다.
  4. import를 누르면 등록합니다. 결과에 +(새로 만듦), ~(수정됨) 목록이 나옵니다.

기본 타입

각 엔티티에 typeName이 없을 때 쓸 타입입니다. CSV는 보통 한 파일에 한 타입이라 여기에 타입을 적고 typeName 열은 생략합니다.

YAML 형식

엔티티 목록을 씁니다. 각 엔티티는 typeName, attributes가 기본이고 labels, classifications도 넣을 수 있습니다.

- typeName: console_demo_table
  attributes:
    qualifiedName: sales.refunds@demo
    name: refunds
    owner: kim
    tier: SILVER
    rowCount: 1200
  labels: [finance]
  classifications:
    - typeName: console_demo_PII
- typeName: DataSet
  attributes:
    qualifiedName: files.export@demo
    name: export

속성 이름은 그 타입에 정의된 이름이어야 합니다. 어떤 속성이 있는지는 타입 메뉴의 정의에서 확인하세요.

JSON 형식

YAML과 같은 구조를 JSON으로 씁니다. REST API 응답처럼 {"entities": [...]}로 감싼 형태도 받습니다.

[
  {
    "typeName": "DataSet",
    "attributes": { "qualifiedName": "files.export@demo", "name": "export" }
  }
]

CSV 형식

한 줄이 엔티티 하나, 한 열이 속성 하나입니다. 첫 줄은 헤더(속성 이름)입니다. 빈 칸은 보내지 않습니다.

qualifiedName,name,owner,tier,rowCount,labels
sales.refunds@demo,refunds,kim,SILVER,1200,finance|daily
sales.coupons@demo,coupons,lee,BRONZE,300,

CSV 헤더 문법

헤더의미셀 예
name문자열 속성orders
tags[]배열 속성 (값은 |로 구분)a|b|c
db@hive_db다른 엔티티 참조 (그 타입의 qualifiedName)sales@prod
columns[]@hive_column참조 배열t.a@prod|t.b@prod
typeName행마다 다른 타입hive_table
classificationsclassification 이름 (| 구분)PII
labels레이블 (| 구분)finance|daily

숫자나 true/false도 문자열로 적으면 Atlas가 속성 타입에 맞게 바꿉니다. 쉼표가 들어간 값은 큰따옴표로 감쌉니다: "a, b"

엔티티끼리 참조하기

예를 들어 데이터베이스와 그 안의 테이블을 한 파일에 넣고, 테이블이 데이터베이스를 가리키게 할 수 있습니다.

typeName,qualifiedName,name,db@hive_db
hive_db,sales@prod,sales,
hive_table,sales.orders@prod,orders,sales@prod

Atlas는 같은 요청 안에서 막 만드는 엔티티를 qualifiedName으로 찾지 못합니다(ATLAS-404-00-00A 오류). 그래서 데모 앱은 100건씩 나눠 보내면서 같은 묶음 안의 참조를 임시 guid로 연결합니다 (EntityFiles.linkWithinBatch). 묶음이 다르면 참조되는 엔티티가 파일에서 먼저 나와야 합니다.

Java 코드로는

List<AtlasEntity> entities = EntityFiles.parse("tables.csv", text, "hive_table");
atlas.entities().createOrUpdate(EntityFiles.linkWithinBatch(entities));

자주 나는 오류

  • qualifiedName is missing: qualifiedName 열이나 속성이 빠졌습니다.
  • no typeName: typeName도 없고 기본 타입도 비었습니다.
  • HTTP 404 / ATLAS-404-00-007 등: 없는 타입 이름이거나, 참조한 엔티티가 Atlas에 없습니다.
  • HTTP 400: 그 타입에 없는 속성 이름이거나 값이 타입과 맞지 않습니다(예: enum에 없는 값).

등록한 뒤에는 엔티티 검색에서 확인하세요. 검색 인덱스 반영에 몇 초 걸릴 수 있습니다.
