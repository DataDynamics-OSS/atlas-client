무엇을 보여주나요?

이 데모 앱의 모든 기능은 Atlas Client 라이브러리를 거쳐 Atlas REST API를 호출합니다. 이 화면은 그 호출을 최근 300건까지 기록합니다. 각 화면 아래의 "이 화면에서 클라이언트가 보낸 요청"은 그 화면 하나의 요청만, 여기서는 모든 화면의 요청을 모아 봅니다.

"버튼 하나 눌렀더니 클라이언트가 실제로 무엇을 했나"를 확인하는 곳입니다. 예를 들어 리니지 등록 한 번이 존재 확인 GET 몇 번과 POST 한 번으로 이뤄진다는 것을 볼 수 있습니다.

상태 코드

200, 204성공 (204는 돌려줄 내용이 없는 성공)
400요청 내용이 잘못됨 (속성 이름, 값 형식, DSL 문법) → AtlasBadRequestException
401, 403로그인 실패, 권한 없음 → AtlasAuthenticationException, AtlasAuthorizationException
404없는 엔티티나 타입 → AtlasNotFoundException
409이미 있음 (같은 이름의 타입 생성 등) → AtlasConflictException
503Atlas가 아직 시작 중이거나 HA의 대기(PASSIVE) 서버 → 자동 재시도
연결 실패Atlas에 닿지 못함 → 자동 재시도 후 AtlasConnectionException

재시도

클라이언트는 일시적인 문제를 자동으로 다시 시도합니다. 같은 경로가 시도 1, 2로 연달아 나오면 재시도한 것입니다.

  • 항상 재시도: 연결 실패, 503. 요청이 서버에 반영되지 않은 게 확실하기 때문입니다.
  • GET/PUT/DELETE만 재시도: 502, 504, 응답 시간 초과. POST는 이미 반영됐을 수 있어 다시 보내지 않습니다.

이 데모 앱은 빠른 응답을 위해 최대 2번까지만 시도하도록 설정했습니다(라이브러리 기본은 3번).

어떻게 기록하나요?

라이브러리의 RequestListener를 씁니다. 여러분의 애플리케이션에서도 같은 방법으로 로그나 메트릭을 남길 수 있습니다.

AtlasClient atlas = AtlasClient.builder()
        .serverUrl("http://atlas:21000")
        .basicAuth("admin", "admin")
        .requestListener(e -> log.info("{} {} -> {} ({} ms, attempt {})",
                e.method(), e.uri(), e.statusCode(), e.elapsed().toMillis(), e.attempt()))
        .build();

본문은 화면에서 최대 2만 글자까지만 보여줍니다. Kafka로 보낸 메시지는 HTTP가 아니므로 여기 나오지 않습니다. "기록 지우기"는 이 목록만 비우며 Atlas에는 영향이 없습니다.
