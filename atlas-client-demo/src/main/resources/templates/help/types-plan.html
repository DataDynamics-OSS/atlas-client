왜 plan이 필요한가요?

Atlas는 이미 만든 타입을 고칠 때 제약이 많습니다. 예를 들어 이미 있는 타입에 필수 속성을 추가하거나 속성의 타입을 바꾸면 거부합니다. 또 여러 타입을 한꺼번에 보낼 때 일부만 적용되면 정리하기 어렵습니다.

그래서 이 클라이언트(TypeDefManager)는 두 단계로 나눕니다. Terraform의 plan/apply와 같은 방식입니다.

  1. plan: 내가 원하는 정의와 서버의 현재 정의를 비교해 만들 것, 고칠 것, 그대로인 것을 보여줍니다. Atlas가 거부할 변경은 ERROR로 미리 표시합니다. 서버에는 아무것도 바꾸지 않습니다(조회만 함).
  2. apply: plan을 다시 계산하고, ERROR가 하나도 없을 때만 서버에 보냅니다. ERROR가 있으면 아무것도 보내지 않습니다.

사용 순서

  1. 편집기에 정의를 YAML(또는 JSON)로 씁니다. 처음에는 예제가 들어 있습니다.
  2. plan을 눌러 결과를 봅니다.
  3. 문제가 없으면 plan 후 apply를 누릅니다.
  4. 같은 내용으로 다시 plan하면 모두 = unchanged가 나옵니다. 이미 적용됐다는 뜻입니다.
기존 타입을 고치려면 타입 목록에서 타입을 열고 "이 정의로 plan 하기"를 누르세요. 현재 정의가 편집기에 채워집니다.

정의 쓰는 법

카테고리별 목록(enumDefs, structDefs, classificationDefs, entityDefs, relationshipDefs, businessMetadataDefs) 아래에 타입을 나열합니다. 필요한 것만 쓰면 됩니다.

enumDefs:
  - name: my_tier
    elementDefs:
      - { value: BRONZE, ordinal: 0 }
      - { value: GOLD, ordinal: 1 }
entityDefs:
  - name: my_table
    superTypes: [DataSet]          # 데이터면 DataSet, 작업이면 Process
    attributeDefs:
      - { name: tier, typeName: my_tier, isOptional: true }
      - { name: rowCount, typeName: long, isOptional: true }
      - { name: tags, typeName: "array<string>", isOptional: true }
classificationDefs:
  - name: my_PII
    entityTypes: [my_table]        # 붙일 수 있는 엔티티 타입
businessMetadataDefs:
  - name: my_quality
    attributeDefs:
      - name: score
        typeName: int
        isOptional: true
        options: { applicableEntityTypes: '["my_table"]' }
  • YAML 들여쓰기는 공백 2칸입니다. 탭은 쓰지 마세요.
  • { … }는 한 줄로 쓴 객체, [ … ]는 한 줄로 쓴 목록입니다.
  • <가 들어간 값(array<string>)은 큰따옴표로 감쌉니다.
  • 정의에 쓰지 않은 기존 속성은 지우지 않고 그대로 둡니다(경고만 표시). 실수로 속성이 사라지지 않습니다.

결과 읽는 법

기호뜻
+ create새로 만들 타입
~ update고칠 타입. 오른쪽에 바뀌는 내용(+ attribute 'tier' 등)
= unchanged이미 원하는 상태

Issues의 ERROR는 Atlas가 거부할 변경이라 apply가 막힙니다. WARNING은 적용은 되지만 확인이 필요한 변경입니다.

ERROR가 나는 대표적인 경우

변경해결 방법
기존 타입에 필수(isOptional: false) 속성 추가isOptional: true로 추가
기존 속성의 typeName 변경새 이름의 속성을 추가
relationship의 양쪽 타입·이름 변경새 relationship 타입을 만듦
같은 이름을 다른 카테고리로 정의이름을 바꿈
존재하지 않는 타입 참조 (superTypes, 속성 타입)참조할 타입을 같이 정의하거나 이름 확인

직접 해 보기: 샘플 데이터를 만든 뒤 아래를 plan하면 ERROR가 나는 것을 볼 수 있습니다.

entityDefs:
  - name: console_demo_table
    superTypes: [DataSet]
    attributeDefs:
      - { name: region, typeName: string, isOptional: false }

isOptional: true로 바꾸면 ~ update로 바뀌고 apply할 수 있습니다.

Java 코드로는

TypeDefManager manager = new TypeDefManager(atlas);
TypePlan plan = manager.plan(TypeDefFiles.fromYaml(yaml));
System.out.println(plan.render());   // 결과 아래 "plan.render() 출력"과 같음
manager.apply(plan);                 // ERROR가 있으면 TypePlanException

요청 기록을 보면 plan은 GET만, apply는 POST(새 타입)와 PUT(수정)을 보낸 것을 확인할 수 있습니다.
