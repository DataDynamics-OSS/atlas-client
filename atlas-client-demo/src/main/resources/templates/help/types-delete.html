왜 미리 검사하나요?

다른 곳에서 쓰는 타입을 지우면 Atlas가 거부하거나, 남은 메타데이터가 깨질 수 있습니다. planDelete()는 지우기 전에 아래 항목을 확인해서 문제가 있으면 ERROR로 알려줍니다.

  • 하위 타입: 이 타입을 superTypes로 상속하는 타입이 남아 있음
  • 참조: 다른 타입의 속성이나 relationship, classification이 이 타입을 가리킴
  • 엔티티 인스턴스: 이 타입의 엔티티가 남아 있음 (soft delete된 것 포함)
  • classification 사용: 지우려는 classification이 엔티티에 붙어 있음

사용 순서

  1. 지울 타입 이름을 쉼표나 공백으로 구분해 넣고 점검을 누릅니다. 예: console_sample_PII console_sample_table console_sample_tier
  2. ERROR가 없으면 삭제 버튼이 나옵니다. 누르면 확인을 묻고 지웁니다.
  3. ERROR가 있으면 메시지대로 먼저 정리합니다.
함께 지우는 타입끼리는 서로 참조해도 괜찮습니다. 한 번의 요청(DELETE /api/atlas/v2/types/typedefs)으로 같이 지웁니다. 목록 밖의 타입이 참조하고 있을 때만 ERROR입니다.
RELATIONSHIP 타입은 남은 관계 인스턴스를 미리 검사할 수 없어 WARNING만 표시합니다. 관계가 남아 있으면 Atlas가 삭제를 거부합니다.

"엔티티가 남아 있다"는 ERROR가 날 때

  1. 엔티티 검색에서 그 타입으로, "삭제된 엔티티 포함"을 체크해 검색합니다.
  2. 각 엔티티 상세 화면에서 delete한 뒤 purge합니다. soft delete만 하면 여전히 남아 있는 것으로 봅니다.
  3. 다시 점검합니다.

샘플 데이터의 타입은 샘플 데이터 화면의 "정리" 버튼이 이 과정을 한 번에 합니다.

Java 코드로는

TypePlan plan = manager.planDelete(List.of("my_table", "my_tier"));
if (!plan.hasErrors()) {
    manager.delete(List.of("my_table", "my_tier"));
}
