엔티티란?

Atlas는 회사의 데이터 자산을 기록해 두는 메타데이터 카탈로그입니다. "어떤 테이블이 있고, 누가 관리하며, 어디서 만들어졌는가"를 저장합니다.

여기서 테이블 하나, 컬럼 하나, ETL 작업 하나처럼 Atlas에 등록된 대상 하나하나를 엔티티(entity)라고 합니다. 엔티티는 반드시 어떤 타입에 속합니다. 타입은 "테이블이라면 이런 속성을 가진다"는 설계도이고, 엔티티는 그 설계도로 만든 실제 기록입니다. 프로그래밍에 비유하면 타입은 클래스, 엔티티는 객체입니다.

타입 (설계도)엔티티 (실제 기록)
hive_tablesales.orders@prod 테이블
hive_columnsales.orders.amount@prod 컬럼
console_demo_jobdaily_sales_etl@demo 작업

엔티티를 구별하는 두 가지 이름

  • guid: Atlas가 붙이는 고유 ID입니다(예: 2caf1346-5f5b-…). 사람이 정하지 않습니다.
  • qualifiedName: 사람이 정하는 고유 이름입니다. 같은 타입 안에서는 겹치면 안 됩니다. 보통 데이터베이스.테이블@클러스터처럼 위치를 담아 짓습니다(예: sales.orders@prod). 이 클라이언트는 guid를 몰라도 타입 + qualifiedName으로 엔티티를 찾고 수정할 수 있게 해 줍니다.

상태(status)

  • ACTIVE: 사용 중인 엔티티
  • DELETED: 삭제된 엔티티. Atlas는 기본적으로 지워도 기록을 남깁니다(soft delete). 완전히 없애려면 엔티티 상세 화면에서 purge합니다.

처음이라면

  1. 메뉴의 샘플 데이터에서 "만들기"를 누릅니다.
  2. 이 화면에서 typeName에 console_demo_table을 넣고 검색합니다.
  3. 결과에서 이름을 누르면 상세 화면으로 이동합니다.

검색 방식 세 가지

방식언제 쓰나쓰는 입력
basic타입, classification, 속성 조건으로 찾을 때 (가장 많이 씀)typeName, classification, query, 속성 필터
DSLSQL과 비슷한 문장으로 복잡한 조건을 줄 때query
full-text어떤 속성에 있든 단어로 찾을 때query

방식을 고른 뒤 그 방식이 쓰는 칸만 채우면 됩니다. 나머지 칸은 무시됩니다.

basic 검색 입력 방법

typeName

찾을 엔티티의 타입 이름입니다. 하위 타입도 함께 찾습니다. 예를 들어 DataSet을 넣으면 DataSet을 상속한 console_demo_table, hive_table 등이 모두 나옵니다. 타입 이름은 타입 메뉴에서 확인할 수 있습니다.

classification

특정 분류(태그)가 붙은 엔티티만 찾습니다. 예: console_demo_PII. typeName을 비우고 classification만 넣어도 됩니다.

query

basic에서는 이름이나 설명에 들어 있는 단어로 걸러냅니다. 예: sales

속성 필터 (속성, 연산자, 값)

엔티티의 속성 값으로 조건을 겁니다. 세 칸을 함께 채웁니다.

속성연산자값의미
ownerEQkimowner가 kim
tierNEQBRONZEtier가 BRONZE가 아님
rowCountGT1000rowCount가 1000보다 큼
nameSTARTS_WITHdailyname이 daily로 시작
descriptionNOT_NULL(비움)description이 있음

자주 쓰는 연산자: EQ(같음), NEQ(다름), LT/GT/LTE/GTE(작음/큼/이하/이상), STARTS_WITH/ENDS_WITH/CONTAINS(문자열 포함), IS_NULL/NOT_NULL(값 없음/있음), IN(여러 값 중 하나).

속성 이름은 엔티티 상세 화면의 "속성" 표 왼쪽 열에 있는 이름을 그대로 씁니다. 필터에 쓰는 속성은 타입 정의에서 검색 인덱스가 걸려 있어야(isIndexable) 결과가 정확합니다.

이 화면이 Atlas에 보내는 요청

typeName console_demo_table, 속성 필터 owner EQ kim으로 검색하면 클라이언트가 아래 JSON을 POST /api/atlas/v2/search/basic으로 보냅니다. 화면 아래 "이 화면에서 클라이언트가 보낸 요청"에서 실제 본문을 볼 수 있습니다.

{"typeName":"console_demo_table","excludeDeletedEntities":true,"limit":25,"offset":0,"entityFilters":{"attributeName":"owner","operator":"=","attributeValue":"kim"}}

Java 코드로는 이렇게 씁니다.

SearchParameters params = SearchParameters.forType("console_demo_table");
params.setEntityFilters(FilterCriteria.of("owner", Operator.EQ, "kim"));
AtlasSearchResult result = atlas.search().basic(params);

DSL 검색 입력 방법

방식을 DSL로 바꾸고 query 칸에 문장을 씁니다. 타입 이름 where 조건이 기본 형태입니다.

console_demo_table
console_demo_table where tier = 'GOLD'
console_demo_table where rowCount > 1000 and owner = 'kim'
console_demo_table where name like 'daily*'
console_demo_table isa console_demo_PII
console_demo_table where owner = 'kim' orderby rowCount desc
console_demo_table select name, owner, rowCount
  • 문자열 값은 작은따옴표로 감쌉니다.
  • isa 분류이름은 그 classification이 붙은 것만 찾습니다.
  • select를 쓰면 엔티티 목록 대신 "select 결과" 표가 나옵니다.
  • 문법이 틀리면 AtlasBadRequestException(HTTP 400)이 화면 위쪽에 표시됩니다.

full-text 검색

query에 단어를 넣으면 이름, 설명 등 모든 텍스트 속성에서 찾습니다. 예: sales. 정확한 조건보다는 "이런 단어가 들어간 게 있나?"를 볼 때 씁니다.

그 밖의 옵션

  • 삭제된 엔티티 포함: 체크하면 DELETED 상태도 결과에 나옵니다. 지운 엔티티를 purge하러 갈 때 씁니다.
  • limit / offset: 한 번에 몇 건을 볼지, 몇 번째부터 볼지입니다. 결과 아래 "다음 →"을 누르면 offset이 늘어납니다. Java에서는 search().basicStream(params)을 쓰면 페이지를 자동으로 넘기며 전부 읽습니다.

결과 읽는 법

  • 표시 이름을 누르면 엔티티 상세 화면으로 갑니다.
  • classification 열에는 직접 붙인 것과 리니지를 따라 전파된 것이 함께 나옵니다. 샘플에서 customers에만 PII를 붙였는데 daily_sales에도 보이는 이유입니다.
  • "전체 약 N"은 Atlas가 알려주는 대략적인 전체 건수입니다.

결과가 안 나올 때

  • 방금 만든 엔티티: 검색은 별도 검색 인덱스(Solr)를 쓰므로 등록 직후 몇 초간 안 보일 수 있습니다. 잠시 뒤 다시 검색하세요.
  • 타입 이름 오타: 없는 타입이면 오류가 표시됩니다. 타입 메뉴에서 이름을 확인하세요.
  • 속성 이름 오타: 그 타입에 없는 속성으로 필터하면 오류가 나거나 결과가 비어 있습니다.
  • 삭제된 엔티티: "삭제된 엔티티 포함"을 체크해 보세요.

엔티티를 새로 등록하려면 CSV/YAML import를 쓰세요.
