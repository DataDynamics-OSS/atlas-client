화면 맨 위

엔티티 이름 아래에 타입(누르면 타입 정의로 이동), qualifiedName, 상태가 있습니다. "리니지 보기"를 누르면 이 엔티티를 중심으로 한 데이터 흐름 그래프로 갑니다.

"정보" 칸의 version은 엔티티가 바뀔 때마다 1씩 늘어납니다. 아래 기능으로 무언가를 바꾼 뒤 이 숫자가 늘었는지 보세요.

속성 vs 관계 속성

  • 속성(attributes): 엔티티 자신의 값입니다. 이름, 설명, owner, rowCount처럼 글자나 숫자입니다. 어떤 속성이 있는지는 타입 정의(attributeDefs)가 정합니다.
  • 관계 속성(relationshipAttributes): 다른 엔티티와의 연결입니다. 테이블의 columns, process의 inputs/outputs 같은 것입니다. 링크를 누르면 연결된 엔티티로 갑니다. 옆에 DELETED가 보이면 지금은 끊긴 과거 연결입니다.

속성 하나 바꾸기 (updateAttribute)

"속성 이름"에 바꿀 속성을, "값"에 새 값을 넣고 버튼을 누릅니다. 다른 속성은 그대로 둡니다.

값은 JSON으로 먼저 해석하고, JSON이 아니면 문자열로 보냅니다.

입력한 값보내는 값
400숫자 400
true불리언 true
GOLD문자열 "GOLD" (JSON이 아니므로)
"400"문자열 "400"
["a","b"]배열

예: 속성 이름 description, 값 매일 새벽 집계되는 매출 테이블

atlas.entities().updateAttribute(guid, "description", "매일 새벽 집계되는 매출 테이블");
enum 타입 속성(예: tier)에는 정의된 값(BRONZE, SILVER, GOLD)만 넣을 수 있습니다. 다른 값을 넣으면 HTTP 400 오류가 납니다.

Classification (분류)

classification은 엔티티에 붙이는 의미 있는 태그입니다. "개인정보(PII)", "민감", "폐기 예정"처럼 데이터 거버넌스 규칙을 표시할 때 씁니다. classification도 타입이라서 미리 정의되어 있어야 하고, 속성을 가질 수도 있습니다.

추가

목록에서 classification을 고르고 "addClassification"을 누릅니다. 목록은 Atlas에 정의된 classification 타입입니다. 샘플 데이터를 만들었다면 console_demo_PII가 있습니다.

리니지로 전파 (propagate)

체크하면 이 엔티티에서 만들어진 하위 데이터에도 같은 classification이 자동으로 붙습니다. 예를 들어 고객 테이블이 개인정보라면, 그걸 읽어 만든 집계 테이블도 개인정보일 가능성이 높기 때문입니다. 전파는 Atlas가 백그라운드에서 처리하므로 다른 엔티티에 나타나기까지 몇 초 걸릴 수 있습니다.

목록에 "전파됨"이라고 표시된 것은 다른 엔티티에서 흘러온 것이라 여기서는 제거할 수 없습니다. 원래 붙인 엔티티에서 제거하세요.

Label (레이블)

label은 미리 정의할 필요 없는 자유로운 꼬리표입니다. "finance", "dashboard"처럼 아무 단어나 붙일 수 있습니다. classification과 달리 속성이나 전파가 없습니다.

  • 입력 칸에 쉼표로 구분해 여러 개를 넣을 수 있습니다: finance, daily
  • 추가: 기존 레이블에 더합니다. 제거: 입력한 것만 뺍니다. 교체: 입력한 것만 남기고 나머지는 지웁니다(빈 칸으로 교체하면 모두 지움).

Business metadata (비즈니스 메타데이터)

기술 속성 외에 업무 정보를 붙이는 기능입니다. 예: 데이터 품질 점수, 담당 부서, 보존 기간. business metadata 타입이 먼저 정의되어 있어야 하고, 그 타입이 이 엔티티 타입에 적용 가능해야 합니다.

입력은 JSON입니다. 바깥 키가 business metadata 이름, 안쪽이 속성과 값입니다.

{
  "console_demo_quality": { "score": 91 }
}
  • overwrite 체크 안 함(기본): 입력한 속성만 바꾸고 나머지는 유지합니다.
  • overwrite 체크: 이 엔티티의 business metadata 전체를 입력한 것으로 바꿉니다. 입력에 없는 것은 지워집니다.

샘플 데이터의 console_demo_quality는 console_demo_table 엔티티에만 쓸 수 있습니다.

감사 이력 (audit)

이 엔티티가 언제, 누구에 의해, 어떻게 바뀌었는지의 기록입니다. 최근 25건을 보여줍니다. 동작 예: ENTITY_CREATE(생성), ENTITY_UPDATE(수정), CLASSIFICATION_ADD(분류 추가), LABEL_ADD(레이블 추가), BUSINESS_ATTRIBUTE_UPDATE(비즈니스 메타데이터 수정). "보기"를 누르면 그때의 내용이 나옵니다.

delete와 purge

  1. delete: 엔티티를 DELETED 상태로 바꿉니다(soft delete). 기록과 감사 이력은 남고, 검색 기본값에서는 안 보입니다. 리니지에서 이 엔티티를 쓰던 연결도 함께 삭제 상태가 됩니다.
  2. purge: DELETED 상태인 엔티티를 완전히 지웁니다. 되돌릴 수 없습니다. 삭제된 엔티티에서만 버튼이 나옵니다.
타입을 지우려면 그 타입의 엔티티가 하나도 없어야 합니다. soft delete만 한 엔티티도 "남아 있는" 것으로 치므로 purge까지 해야 합니다.

서버 응답 JSON

맨 아래를 펼치면 Atlas가 돌려준 원본 JSON(AtlasEntityWithExtInfo)이 있습니다. referredEntities에는 관계로 연결된 엔티티의 정보가 함께 들어 있습니다.

오류가 나면

화면 위쪽 빨간 상자에 클라이언트 예외 이름, HTTP 상태, Atlas 오류 코드가 나옵니다.

  • AtlasNotFoundException / ATLAS-404-00-008: 없는 classification 이름
  • AtlasBadRequestException (400): 속성 이름이 틀렸거나 값의 형식이 맞지 않음
  • ATLAS-406-00-001: classification 전파 작업이 진행 중. 잠시 뒤 다시 시도
