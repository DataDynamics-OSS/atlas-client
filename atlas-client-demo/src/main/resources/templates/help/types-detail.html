두 가지 보기

  • export YAML: 사람이 읽고 고치기 좋은 형태입니다. guid, 생성 시간, version 같은 서버가 붙인 필드를 뺐기 때문에 그대로 복사해 plan/apply에 쓰거나 다른 Atlas에 옮길 수 있습니다.
  • 서버 응답 JSON: Atlas가 돌려준 원본입니다. 서버 필드가 모두 있습니다.

정의 읽는 법 (ENTITY 타입)

entityDefs:
  - name: console_demo_table          # 타입 이름
    superTypes: [DataSet]             # 상속하는 타입
    attributeDefs:                    # 이 타입이 추가로 가지는 속성
      - name: tier
        typeName: console_demo_tier   # 속성 값의 타입 (enum)
        isOptional: true              # 비워도 되는가
        cardinality: SINGLE           # 값 하나 (LIST/SET이면 여러 개)
      - name: rowCount
        typeName: long
        isOptional: true
필드뜻
typeName값의 타입. string, int, long, boolean, date, enum 이름, array<string>, 다른 엔티티 타입 이름(참조) 등
isOptionalfalse면 필수 속성. 엔티티를 만들 때 반드시 값을 넣어야 합니다.
isUnique같은 타입 안에서 값이 겹치면 안 됨 (qualifiedName이 대표적)
isIndexable검색 인덱스를 만듦. 검색 필터에 쓸 속성이면 켭니다.
cardinalitySINGLE(하나), LIST(순서 있는 여러 개), SET(중복 없는 여러 개)

여기 보이는 속성은 이 타입이 직접 정의한 것뿐입니다. 상속받은 속성(qualifiedName, name, owner 등)은 superTypes의 정의에 있습니다.

다른 카테고리

  • ENUM: elementDefs에 허용 값 목록이 있습니다.
  • CLASSIFICATION: entityTypes는 이 분류를 붙일 수 있는 엔티티 타입입니다(비어 있으면 모든 타입).
  • RELATIONSHIP: endDef1, endDef2가 연결되는 두 타입과 각 쪽의 속성 이름입니다. relationshipCategory가 COMPOSITION이면 부모를 지울 때 자식도 지워집니다.
  • BUSINESS_METADATA: 속성마다 options.applicableEntityTypes에 적용 가능한 엔티티 타입이 있습니다.
