리니지는 어떻게 만들어지나요?

Atlas에 리니지를 따로 저장하는 곳은 없습니다. 프로세스 엔티티의 inputs(읽는 데이터셋)와 outputs(쓰는 데이터셋)를 등록하면, 그 연결이 곧 리니지가 됩니다. 예를 들어 "주문과 고객을 읽어 일별 매출을 만든다"는 작업 하나를 등록하면 orders → 작업 → daily_sales, customers → 작업 → daily_sales 화살표가 생깁니다.

입력 항목

process 타입Process를 상속한 타입. 일반 용도면 Process, 샘플 데이터가 있으면 console_demo_job
qualifiedName이 작업의 고유 이름. 예: etl.refund_summary@demo. 같은 이름으로 다시 등록하면 수정됩니다.
name, description사람이 읽는 이름과 설명 (선택)
inputs / outputs한 줄에 하나씩 타입:qualifiedName
 
console_demo_table:raw.orders@demo
console_demo_table:raw.customers@demo
  • 콜론(:) 앞이 타입, 뒤가 qualifiedName입니다. qualifiedName 안에 콜론이 있어도 첫 콜론만 구분자로 씁니다 (예: hdfs_path:hdfs://nn:8020/data).
  • 빈 줄과 #으로 시작하는 줄은 무시합니다.

없는 엔티티 처리

inputs/outputs에 적은 데이터셋이 아직 Atlas에 없을 때 어떻게 할지 고릅니다.

정책동작언제
FAIL (기본)미리 확인해서 하나라도 없으면 아무것도 보내지 않고 없는 목록을 보여줌데이터셋이 반드시 먼저 등록되어 있어야 할 때
CREATE없는 데이터셋을 이름만 있는 stub으로 같이 만듦리니지를 먼저 그리고 상세는 나중에 채울 때
NO_CHECK확인 없이 바로 보냄. 없으면 Atlas가 오류를 냄이미 있는 게 확실하고 확인 요청을 아끼고 싶을 때

직접 해 보기: outputs에 DataSet:not.there@demo처럼 없는 것을 넣고 FAIL로 등록하면 오류 상자에 없는 목록이 나옵니다. CREATE로 바꾸면 stub을 만들고 등록됩니다. 요청 기록에서 FAIL은 존재 확인 GET만 하고 POST를 보내지 않은 것을 볼 수 있습니다.

stub을 만들 때 그 타입에 필수 속성이 있으면 Atlas가 거부합니다. 그럴 때는 데이터셋을 먼저 import로 만드세요.

컬럼 리니지 (선택)

테이블 단위보다 자세하게, "출력 컬럼이 어떤 입력 컬럼들로 계산되는지"를 기록합니다. 한 줄에 출력 컬럼 하나입니다.

hive_column:mart.daily_sales.amount@prod <- hive_column:raw.orders.price@prod, hive_column:raw.orders.qty@prod

컬럼 리니지는 기본으로 hive_column_lineage 타입 엔티티로 만들어지므로, Hive 모델이 있는 Atlas에서 씁니다.

전송 경로

  • REST (bulk): 프로세스, 컬럼 리니지, stub을 한 번의 요청으로 보냅니다. 전부 성공하거나 전부 실패합니다. 결과에 guid가 바로 나옵니다.
  • Kafka (ATLAS_HOOK): 같은 내용을 Hive·Spark 훅처럼 Kafka 메시지로 보냅니다. Atlas가 나중에 처리하므로 결과는 잠시 뒤 리니지 화면에서 확인합니다. Kafka가 설정된 경우에만 고를 수 있습니다.

다시 등록하면?

같은 qualifiedName으로 inputs/outputs를 바꿔 등록하면 새 값으로 교체됩니다. 이전 연결은 Atlas에서 "삭제됨" 상태로 남고, 리니지 화면은 기본으로 현재 연결만 보여줍니다.

프로세스를 지우면(엔티티 상세에서 delete) 그 리니지 연결도 사라집니다.

Java 코드로는

AtlasLineage lineage = new AtlasLineage(atlas).missingEntities(MissingEntityPolicy.CREATE);
lineage.process("console_demo_job", "etl.refund_summary@demo")
        .inputs(EntityRef.of("console_demo_table", "raw.orders@demo"))
        .outputs(EntityRef.of("DataSet", "mart.refund_summary@demo"))
        .attribute("schedule", "0 3 * * *")
        .register();
