왜 필요한가요?

Atlas는 엔티티 하나하나가 형식에 맞는지만 검사합니다. 그래서 형식은 맞지만 의미상 이상한 상태가 쌓일 수 있습니다. 예를 들어 테이블을 지웠는데 그 테이블을 읽던 작업은 남아 있으면, 리니지가 중간에 끊깁니다. 이 화면은 그런 문제를 찾아 목록으로 보여줍니다. 정기적으로 돌려 메타데이터를 깨끗하게 유지할 때 씁니다.

찾는 문제

종류뜻보통 원인
ORPHAN_PROCESSinputs도 outputs도 없는 프로세스. 리니지에 아무 기여를 못 함잘못 등록했거나 연결된 데이터셋이 모두 지워짐
INCOMPLETE_PROCESSinputs나 outputs 한쪽만 있는 프로세스한쪽 데이터셋이 지워짐, 등록 누락
DELETED_REFERENCE현재 연결이 삭제된 엔티티를 가리킴데이터셋을 지웠는데 프로세스를 고치지 않음
DUPLICATE같은 타입에 qualifiedName이 같은 ACTIVE 엔티티가 여러 개qualifiedName 규칙이 일관되지 않은 수집

입력 방법

  • process 타입: 이 타입과 그 하위 타입의 모든 프로세스를 검사합니다. 기본 Process는 모든 프로세스를 뜻합니다. 프로세스 검사를 건너뛰려면 비웁니다.
  • 중복 검사할 타입: qualifiedName 중복을 찾을 타입입니다. 쉼표로 여러 개를 넣을 수 있습니다. 예: console_demo_table, DataSet

직접 해 보기

  1. 샘플 데이터를 만들고 여기서 점검하면 "문제 없음"이 나옵니다.
  2. raw.orders와 raw.customers 엔티티를 상세 화면에서 delete합니다.
  3. 잠시 뒤 다시 점검하면 daily_sales_etl@demo가 INCOMPLETE_PROCESS로 나옵니다(입력이 모두 사라짐).
  4. 샘플 화면에서 "다시 만들기"를 누르면 원래대로 돌아옵니다.

알아 둘 점

  • 점검은 검색 인덱스로 대상을 찾으므로 방금 바꾼 내용은 몇 초 뒤에 반영됩니다.
  • 프로세스가 많으면 100개씩 묶어 조회하므로 요청 기록에 bulk 조회가 여러 번 나옵니다.
  • 찾기만 하고 고치지는 않습니다. 결과의 qualifiedName을 눌러 엔티티를 직접 정리하세요.

Java 코드로는

ConsistencyChecker checker = new ConsistencyChecker(atlas);
List<Finding> findings = new ArrayList<>(checker.checkProcesses("Process"));
findings.addAll(checker.checkDuplicates("hive_table"));
