Atlas와 Kafka의 관계

Atlas는 REST API 외에 Kafka 토픽 두 개로도 외부와 주고받습니다.

Hive·Spark 훅, 이 데모 앱
   │
   │  ATLAS_HOOK      "이 엔티티를 만들어 줘"
   ▼
 Atlas
   │
   │  ATLAS_ENTITIES  "이 엔티티가 만들어졌어"
   ▼
카탈로그 동기화, 알림, 이 데모 앱
  • ATLAS_HOOK: Atlas에게 보내는 요청 토픽입니다. Hive나 Spark의 Atlas 훅이 테이블과 리니지를 이 토픽으로 보냅니다. Atlas가 읽어서 처리합니다.
  • ATLAS_ENTITIES: Atlas가 내보내는 알림 토픽입니다. 엔티티가 생기거나 바뀌거나 지워지면 이벤트가 나옵니다. 다른 시스템이 이걸 구독해 변경을 따라갑니다.

REST와 무엇이 다른가요?

RESTKafka hook
결과바로 성공/실패와 guid를 받음Kafka가 받았다는 것만 앎. Atlas 처리는 나중
실패하면오류 응답Atlas 서버 로그에만 남음
장점즉시 확인Atlas가 잠시 멈춰도 메시지가 쌓였다 처리됨. 대량 전송에 유리

실패가 서버 로그에만 남기 때문에, 클라이언트(AtlasHookPublisher)는 Atlas가 처리할 수 없는 메시지를 보내기 전에 검사해서 거부합니다. 예: qualifiedName이 빈 delete. 이때는 화면 위쪽에 IllegalArgumentException이 나오고 Kafka로는 아무것도 가지 않습니다.

메시지 보내기

위쪽 탭에서 종류를 고릅니다.

createOrUpdate (ENTITY_CREATE_V2)

엔티티를 만들거나 수정합니다. import의 YAML과 같은 형식입니다.

- typeName: DataSet
  attributes:
    qualifiedName: console.from_kafka@demo
    name: from_kafka

partialUpdateByQualifiedName (ENTITY_PARTIAL_UPDATE_V2)

지정한 엔티티의 일부 속성만 바꿉니다. typeName과 qualifiedName으로 엔티티를 찾고, 바꿀 속성을 JSON으로 씁니다.

{"description": "partially updated through ATLAS_HOOK"}

deleteByQualifiedName (ENTITY_DELETE_V2)

typeName과 qualifiedName으로 엔티티를 지웁니다(soft delete).

보낸 뒤

초록 상자에 PublishResult가 나옵니다. topic, partition, offset은 메시지가 Kafka 어디에 저장됐는지이고, parts는 나눠 보낸 메시지 수입니다(1MB를 넘으면 압축하고, 그래도 크면 나눕니다). 이건 Kafka가 받았다는 뜻이지 Atlas가 처리했다는 뜻이 아닙니다. 처리되면 아래 이벤트 목록에 나타납니다.

이벤트 목록 (ATLAS_ENTITIES)

데모 앱이 시작될 때부터 받은 이벤트를 최근 200건까지 보여주고, 새 이벤트는 새로고침 없이 맨 위에 추가됩니다 (제목 옆이 "실시간 수신 중"이면 연결된 상태). REST로 한 변경(다른 메뉴)도 여기에 나타납니다.

동작언제
ENTITY_CREATE엔티티 생성
ENTITY_UPDATE엔티티 수정
ENTITY_DELETE엔티티 삭제
CLASSIFICATION_ADD / DELETE / UPDATE분류 추가·제거·변경
RELATIONSHIP_CREATE / DELETE관계 생성·삭제 (리니지 연결 포함)
  • 필터: 입력한 글자가 들어간 행만 보입니다. 예: DELETE, demo
  • 원문: Atlas가 보낸 알림 전체입니다.
Atlas 2.3에서 확인한 동작: REST의 부분 수정(엔티티 상세의 updateAttribute 등)은 ENTITY_UPDATE 이벤트를 내지 않지만, Kafka hook의 partial update는 ENTITY_UPDATE를 냅니다. 두 탭을 번갈아 써 보며 비교해 보세요.

이벤트가 안 올 때

  • 메시지를 보낸 뒤 몇 초 기다리세요. Atlas가 순서대로 처리합니다.
  • 메시지 내용이 틀렸으면(없는 타입, 필수 속성 누락) Atlas가 처리에 실패하고 서버 로그에만 남깁니다. docker compose -f docker/compose.yaml logs atlas에서 확인하세요.
  • 대시보드에서 "ATLAS_ENTITIES 리스너" 상태가 "수신 중"인지 확인하세요.

Java 코드로는

try (AtlasHookPublisher hook = AtlasHookPublisher.builder()
        .bootstrapServers("kafka:9092").user("etl").build()) {
    hook.createOrUpdate(entity);
    hook.deleteByQualifiedName("DataSet", "console.from_kafka@demo");
}

AtlasEntityChangeListener.builder()
        .bootstrapServers("kafka:9092")
        .groupId("my-sync")
        .handler(e -> System.out.println(e.getOperationType() + " " + e.qualifiedName()))
        .build()
        .start();

Kafka로 보내는 메시지는 HTTP 요청이 아니므로 화면 아래 요청 기록에는 나오지 않습니다.
