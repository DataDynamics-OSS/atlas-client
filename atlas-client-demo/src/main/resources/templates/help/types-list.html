타입이란?

Atlas에 무언가를 등록하려면 먼저 "그것이 어떤 모양인지"를 정해야 합니다. 이 설계도가 타입(type)입니다. 예를 들어 hive_table 타입은 "테이블은 name, owner, columns, db를 가진다"고 정합니다. 실제 테이블 하나하나는 이 타입의 엔티티로 등록됩니다.

Atlas에는 Hive, Kafka, HDFS 등을 위한 타입이 기본으로 들어 있고(serviceType으로 구분), 필요하면 직접 만들 수도 있습니다.

카테고리

타입은 쓰임새에 따라 여섯 가지로 나뉩니다. 위쪽 "카테고리"로 걸러 볼 수 있습니다.

카테고리무엇인가예
ENTITY등록 대상의 설계도. 가장 중요합니다.hive_table, DataSet, Process
CLASSIFICATION엔티티에 붙이는 분류 태그. 리니지로 전파될 수 있습니다.PII, console_demo_PII
ENUM정해진 값 목록. 속성 값으로 그 중 하나만 허용합니다.console_demo_tier (BRONZE/SILVER/GOLD)
STRUCT여러 값을 묶은 구조. 속성의 타입으로 씁니다.hive_serde
RELATIONSHIP두 엔티티 타입 사이의 연결 방법hive_table_columns (테이블↔컬럼)
BUSINESS_METADATA엔티티에 붙이는 업무 정보 묶음console_demo_quality

상속 (superTypes)

ENTITY 타입은 다른 타입을 상속해 속성을 물려받습니다. 기본 계층은 이렇습니다.

Referenceable      qualifiedName
 └─ Asset          name, description, owner
     ├─ DataSet    데이터 (테이블, 파일, 토픽)
     │   └─ hive_table, console_demo_table …
     └─ Process    작업. inputs, outputs
         └─ hive_process, console_demo_job …

오른쪽은 그 타입이 추가하는 대표 속성입니다. 하위 타입은 위쪽 속성을 모두 물려받습니다. 예를 들어 console_demo_table은 qualifiedName, name, owner를 따로 정의하지 않아도 가집니다.

DataSet과 Process가 리니지의 핵심입니다. 리니지는 "DataSet → Process → DataSet" 모양의 그래프이기 때문입니다. 새 타입을 만들 때 데이터라면 DataSet을, 작업이라면 Process를 상속하면 리니지에 바로 나타납니다.

이 화면 사용법

  • 카테고리 / 이름 포함: 목록을 걸러냅니다. 예: 카테고리 ENTITY, 이름 demo
  • 이름을 누르면 정의 전체(속성 목록 등)를 볼 수 있습니다.
  • serviceType으로 export: 그 serviceType의 정의를 YAML 파일로 내려받습니다. 예: hive. guid나 생성 시간처럼 서버가 붙인 필드는 빼므로, 다른 Atlas에 그대로 적용할 수 있습니다.
  • 위쪽 링크 plan/apply에서 타입을 만들거나 고치고, 안전한 삭제에서 지웁니다.

이 화면이 쓰는 API

List<AtlasTypeDefHeader> headers = atlas.types().getHeaders();   // 이름, 카테고리, guid만
Optional<AtlasBaseTypeDef> def = atlas.types().findByName("console_demo_table");
AtlasTypesDef hive = new TypeDefManager(atlas).exportByServiceType("hive");

getHeaders()는 정의 전체가 아니라 요약만 받아 오므로 가볍습니다. 화면 아래 요청 기록에서 GET /api/atlas/v2/types/typedefs/headers 한 번만 호출한 것을 볼 수 있습니다.
